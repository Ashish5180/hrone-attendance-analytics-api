# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33-37) | Timezone mismatch and incorrect boundary logic: replaced hour/minute on UTC punch-in instead of converting to IST. Computed `int((punch_in - start).total_seconds() / 60)` and checked `minutes > 10`. For 09:40:01 (601 seconds), `int(601/60) = 10`, `10 > 10` is False, returning 0 late minutes instead of 10 (violating R2). | Punch-in at 09:40:01 returned 0 late minutes; punch-in with UTC timestamps computed incorrect local shift hours. | Converted punch-in to IST, calculated elapsed seconds `diff = (punch_in_ist - start_ist).total_seconds()`, checked strict grace period `diff > 600`, and returned floor minutes `int(diff // 60)`. |
| 2 | `compute_work_hours` (lines 40-42) | Used Python's built-in `round(..., 2)`, which implements banker's rounding (round-half-to-even) instead of round-half-up (R4, R8). | Work intervals resulting in exact half-cent hours (e.g., 2.525 hours) rounded down to 2.52 instead of up to 2.53. | Implemented `round_half_up` helper using `decimal.Decimal` with `ROUND_HALF_UP`. |
| 3 | `compute_overtime` (lines 44-48) | Missing 30-minute threshold check (R3); awarded overtime for any minute past shift end. Anchored shift end to the punch-in date without handling overnight shifts ending the next day. Subtracted naive from IST-aware datetimes. | Punch-out at 18:35 awarded 5 overtime minutes instead of 0. Overnight shifts crashed with `TypeError` or computed negative overtime. | Enforced `mins >= 30` else 0. Added overnight shift check (`shift_end <= shift_start`) to advance shift end by 1 day, and ensured timezone-aware comparisons. |
| 4 | `punch_in` / date calculation (lines 100-103) | Extracted `d = ts.date().isoformat()` from UTC `ts` without converting to IST or applying overnight shift logic (R1). Punches between 00:00 and 05:30 IST were assigned the previous UTC day. Early morning punches for overnight shifts were not mapped to the previous calendar day. | Punch-ins during early IST morning received incorrect dates; overnight shift punches split across days. | Implemented `compute_attendance_date` with IST conversion and overnight shift boundary check (`punch_secs < end_secs` maps to previous day). |
| 5 | Database setup (lines 22-23) | No database indexes created. Missing unique constraints on `employees.emp_code` and `attendance_logs.(emp_code, date)`. | Duplicate employee codes and duplicate daily punch-ins could be inserted. Queries at 100k scale triggered slow collection scans (`COLLSCAN`). | Added a FastAPI `lifespan` handler creating idempotent unique indexes on `employees.emp_code` and `attendance_logs.(emp_code, date)`, plus compound indexes for sorting and filtering. |
| 6 | `GET /health` (lines 72-74) | Hardcoded `{"status": "ok"}` with 200 without checking if MongoDB is responsive. Contract requires 200 when MongoDB answers, else 503. | Stopping MongoDB daemon still resulted in `/health` returning 200 OK. | Executed `db.command("ping")` in a try-except block, raising `HTTPException(503, "MongoDB unavailable")` on failure. |
| 7 | `POST /employees` (lines 78-86) | Check-then-act race condition via `find_one` without database-level uniqueness enforcement. Used naive `datetime.now()` and returned raw datetime instead of epoch milliseconds. | Firing concurrent requests with identical `emp_code` created duplicate employee records. Response schema failed OpenAPI integer timestamp format. | Relied on unique index on `emp_code` catching `DuplicateKeyError` to return 409 Conflict. Stored UTC datetimes and formatted `created_at` as epoch milliseconds. |
| 8 | `EmployeeIn` model (lines 53-61) | Missing Pydantic validation: accepted invalid `emp_code` patterns, invalid emails, non-24-hour shift times, identical shift start/end times, and malformed `joined_on` dates. | Sending invalid employee codes or malformed emails returned 201 Created instead of 422 Unprocessable Entity. | Added field validators with explicit regex patterns (`EMP\d{4,6}`, email, `HH:MM`) and a model validator ensuring distinct shift start and end times. |
| 9 | `GET /employees` (lines 89-96) | Off-by-one pagination bug: `skip = page * page_size` caused page 1 to skip the first 20 records. Total count ignored filters (`count_documents({})` counted the entire collection). Missing sort by `emp_code` ascending. | Page 1 returned the 2nd page of results; total remained constant when filtering by department; results returned in arbitrary order. | Changed skip offset to `(page - 1) * page_size`, passed filter `q` to `count_documents(q)`, added `.sort("emp_code", ASCENDING)`, and added query constraints (`ge=1`, `le=100`). |
| 10 | `POST /attendance/punch-in` (lines 100-106) | Unhandled `TypeError` when employee does not exist (`emp = None`, causing `emp["shift_start"]` to raise `TypeError` -> 500 error instead of 404). Check-then-act `find_one` allowed race conditions. Accepted invalid statuses and did not truncate timestamp to whole seconds. | Non-existent employee crashed with HTTP 500. Concurrent punch-in requests created duplicate logs for the same day. Unrecognized statuses were accepted. | Added check `if not emp: raise HTTPException(404)`. Enforced unique compound index `{"emp_code": 1, "date": 1}` and handled `DuplicateKeyError` (409). Validated status against `PRESENCE_STATUSES` and truncated timestamp to seconds (R1). |
| 11 | `GET /attendance` (lines 124-150) | In-memory pagination and sorting: loaded all matching documents into memory via `list(find(q))` and sorted in Python. At 100k records, this causes memory exhaustion and multi-second latency. Missing parameter validation (`date_from <= date_to`, valid dates and statuses). | Memory spikes and slow queries on large collections. Requesting `date_from > date_to` was processed without error. | Pushed sorting and pagination into MongoDB via `.sort([("date", DESCENDING), ("emp_code", ASCENDING)]).skip(skip).limit(page_size)` backed by compound index. Added date format, range, and status validation. |
| 12 | Attendance response formatting (lines 119-121, 149-150) | Injected an extraneous `id` field not defined in OpenAPI schema. Returned raw datetimes instead of epoch milliseconds or null. | Response did not match `AttendanceRecord` schema; frontend clients expecting integer epoch timestamps received datetime objects or strings. | Created centralized `format_record` serializer adhering strictly to OpenAPI schema with integer epoch milliseconds and no extra `id` field. |

## Items Examined and Decided Not to be Defects

1. **Default Shift Times**: Defaulting `shift_start = "09:30"` and `shift_end = "18:30"` in `EmployeeCreate` was verified against company policy and schema definitions as valid sensible defaults.
2. **MongoDB BSON Storage Format**: Storing timestamps as native BSON `Date` (UTC) in MongoDB while exchanging epoch milliseconds integer values via the JSON REST API is standard MongoDB practice and matches `DATA_MODEL.md`.
3. **Collection Names**: Using collection names `employees` and `attendance_logs` conforms directly to `sample_seed.py`, `DATA_MODEL.md`, and grading specifications.
